Question: Show me the top 10 counsellors with the most students and how many of those students are at each stage from pre-application to enrollment.

```sql
SELECT
    c.counsellor_name,
    COUNT(DISTINCT s.student_id) AS total_students,
    COUNT(DISTINCT CASE WHEN s.current_student_status = 'Pre Application' THEN s.student_id END) AS pre_application,
    COUNT(DISTINCT CASE WHEN s.current_student_status = 'Initial Counselling Completed' THEN s.student_id END) AS counselling_completed,
    COUNT(DISTINCT CASE WHEN csj.course_status IN ('Form Submitted – Portal Pending', 'Form Submitted – Completed', 'Walkin Completed', 'Walkin Marked', 'Exam/Interview Scheduled', 'Offer Letter/Results Pending', 'Offer Letter/Results Released', 'Ready For Admission') THEN csj.student_id END) AS applications,
    COUNT(DISTINCT CASE WHEN csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid') THEN csj.student_id END) AS admissions,
    COUNT(DISTINCT CASE WHEN csj.course_status = 'Enrolled' THEN csj.student_id END) AS enrolled
FROM counsellors c
JOIN students s ON c.counsellor_id = s.assigned_counsellor_id
LEFT JOIN course_status_journeys csj ON s.student_id = csj.student_id
GROUP BY c.counsellor_id, c.counsellor_name
HAVING COUNT(DISTINCT s.student_id) > 0
ORDER BY total_students DESC
LIMIT 10;
```
Key patterns: one row per counsellor, one column per stage via CASE WHEN. Never return one row per status (long format). Always include total_students. No status = 'active' filter. Application stage uses IN list with all application-stage statuses. Admission excludes blocked admissions via fee_type filter.

Question: For each counsellor, show me how many students reached admission or enrollment, how many remarks they logged, upcoming and overdue callbacks, and their conversion rate.

```sql
SELECT
    c.counsellor_name,
    COUNT(DISTINCT s.student_id) AS total_students,
    (COUNT(DISTINCT CASE WHEN csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid') THEN csj.student_id END) + COUNT(DISTINCT CASE WHEN csj.course_status = 'Enrolled' THEN csj.student_id END)) AS converted_students,
    COUNT(DISTINCT sr.remark_id) AS total_remarks,
    COUNT(DISTINCT CASE WHEN sr.callback_date >= CURRENT_DATE THEN sr.remark_id END) AS upcoming_callbacks,
    COUNT(DISTINCT CASE WHEN sr.callback_date < CURRENT_DATE THEN sr.remark_id END) AS overdue_callbacks,
    ROUND(
        (COUNT(DISTINCT CASE WHEN csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid') THEN csj.student_id END) + COUNT(DISTINCT CASE WHEN csj.course_status = 'Enrolled' THEN csj.student_id END))::numeric
        / NULLIF(COUNT(DISTINCT s.student_id), 0) * 100, 2
    ) AS conversion_rate_pct
FROM counsellors c
JOIN students s ON c.counsellor_id = s.assigned_counsellor_id
LEFT JOIN course_status_journeys csj ON s.student_id = csj.student_id
LEFT JOIN student_remarks sr ON s.student_id = sr.student_id AND sr.counsellor_id = c.counsellor_id
GROUP BY c.counsellor_id, c.counsellor_name
HAVING COUNT(DISTINCT s.student_id) > 0
ORDER BY total_students DESC;
```
Key patterns: NO status = 'active' filter. NO is_partner filter. Callbacks count remark_id not student_id. Always include total_students. No LIMIT on full summary queries.

Question: How many students are currently in the application stage for programs at Amity University?

```sql
SELECT COUNT(DISTINCT csj.student_id) AS applications
FROM course_status_journeys csj
JOIN university_courses uc ON csj.course_id = uc.course_id
WHERE uc.university_name ILIKE '%amity%'
  AND csj.course_status IN ('Form Submitted – Portal Pending', 'Form Submitted – Completed', 'Walkin Completed', 'Walkin Marked', 'Exam/Interview Scheduled', 'Offer Letter/Results Pending', 'Offer Letter/Results Released', 'Ready For Admission')
  AND csj.student_id IN (SELECT student_id FROM students);
```
Key patterns: "application stage", "form filled", "form fills", "applied", "walkin", "exam scheduled", "offer letter", "ready for admission" ALL mean `course_status IN ('Form Submitted – Portal Pending', 'Form Submitted – Completed', 'Walkin Completed', 'Walkin Marked', 'Exam/Interview Scheduled', 'Offer Letter/Results Pending', 'Offer Letter/Results Released', 'Ready For Admission')` on course_status_journeys. NEVER use `students.current_student_status` for Application/Admission/Enrolled stages. NEVER use `course_status = 'Application'` in Regular LMS. For Application/Admission/Enrolled → always use course_status_journeys.

Question: Show me how many students are at pre-application, application, admission, and enrolled for each university.

```sql
WITH stage_priority AS (
    SELECT
        uc.university_name,
        s.student_id,
        MAX(
            CASE
                WHEN csj.course_status = 'Enrolled'        THEN 4
                WHEN csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid') THEN 3
                WHEN csj.course_status IN ('Form Submitted – Portal Pending', 'Form Submitted – Completed', 'Walkin Completed', 'Walkin Marked', 'Exam/Interview Scheduled', 'Offer Letter/Results Pending', 'Offer Letter/Results Released', 'Ready For Admission') THEN 2
                WHEN s.current_student_status = 'Pre Application' THEN 1
                ELSE 0
            END
        ) AS final_stage_rank
    FROM students s
    LEFT JOIN course_status_journeys csj ON s.student_id = csj.student_id
    LEFT JOIN university_courses uc ON csj.course_id = uc.course_id
    GROUP BY uc.university_name, s.student_id
)
SELECT
    university_name,
    COUNT(*) FILTER (WHERE final_stage_rank = 1) AS pre_application,
    COUNT(*) FILTER (WHERE final_stage_rank = 2) AS applications,
    COUNT(*) FILTER (WHERE final_stage_rank = 3) AS admissions,
    COUNT(*) FILTER (WHERE final_stage_rank = 4) AS enrolled
FROM stage_priority
GROUP BY university_name
ORDER BY applications DESC;
```
Key patterns: always use a stage_rank CTE to find each student's highest stage before counting per university. Never count the same student across multiple stage buckets. For Pre Application use students.current_student_status, for Application/Admission/Enrolled use course_status_journeys.course_status with proper IN list for applications and fee_type filter for admissions. Join path: students → course_status_journeys → university_courses. No LIMIT.

Question: On average, how many days from when a student first enters the system to when they get admission or enroll?

```sql
SELECT
    AVG(EXTRACT(EPOCH FROM (sub.first_milestone_date - s.created_at)) / 86400) AS avg_tat_days
FROM students s
JOIN (
    SELECT 
        student_id,
        course_id,
        MIN(created_at) AS first_milestone_date
    FROM course_status_journeys
    WHERE (course_status = 'Admission' AND fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid'))
       OR course_status = 'Enrolled'
    GROUP BY student_id, course_id
) sub ON s.student_id = sub.student_id
WHERE s.created_at IS NOT NULL
  AND sub.first_milestone_date IS NOT NULL;
```

For university-level TAT (breakdown per university):
```sql
SELECT
    uc.university_name,
    COUNT(DISTINCT s.student_id) AS converted_students,
    ROUND(AVG(EXTRACT(EPOCH FROM (sub.first_milestone_date - s.created_at)) / 86400)::numeric, 1) AS avg_tat_days,
    ROUND(MIN(EXTRACT(EPOCH FROM (sub.first_milestone_date - s.created_at)) / 86400)::numeric, 1) AS min_tat_days,
    ROUND(MAX(EXTRACT(EPOCH FROM (sub.first_milestone_date - s.created_at)) / 86400)::numeric, 1) AS max_tat_days
FROM students s
JOIN (
    SELECT 
        student_id,
        course_id,
        MIN(created_at) AS first_milestone_date
    FROM course_status_journeys
    WHERE (course_status = 'Admission' AND fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid'))
       OR course_status = 'Enrolled'
    GROUP BY student_id, course_id
) sub ON s.student_id = sub.student_id
JOIN university_courses uc ON sub.course_id = uc.course_id
WHERE s.created_at IS NOT NULL
  AND sub.first_milestone_date IS NOT NULL
GROUP BY uc.university_name
ORDER BY converted_students DESC;
```
Key patterns: TAT = course_status_journeys.created_at − students.created_at. Use course_status_journeys for Admission/Enrolled timestamps with proper fee_type filter for admissions. NEVER use students.updated_at for TAT — it doesn't reflect when they reached Admission/Enrolled. NEVER join student_remarks for TAT — remark timestamps are logged after status change and produce wrong intervals. Always compute (later − earlier): csj.created_at − s.created_at, never the reverse. No LIMIT.

Question: Show me monthly lead counts over the last 6 months broken down by source.

```sql
SELECT
    DATE_TRUNC('month', s.created_at) AS month,
    s.source,
    COUNT(*) AS lead_count
FROM students s
WHERE s.created_at >= DATE_TRUNC('month', CURRENT_DATE - INTERVAL '5 months')
GROUP BY DATE_TRUNC('month', s.created_at), s.source
ORDER BY month DESC, lead_count DESC;
```
Key patterns: use COUNT(*) for lead counts — each student row is one lead, no DISTINCT needed. Use DATE_TRUNC for month bucketing — no 5h30m offset on DATE_TRUNC operations. Do NOT filter by current_student_status — "monthly lead count" means all students created in that period regardless of their current stage. No LIMIT.

Question: Show me students who are at the application, admission, or enrolled stage but have not had a remark in the last 7 days.

```sql
SELECT
    s.student_name,
    s.student_email,
    s.student_phone,
    c.counsellor_name,
    csj.course_status,
    MAX(sr.created_at) AS last_remark_date
FROM students s
JOIN course_status_journeys csj ON s.student_id = csj.student_id
JOIN counsellors c ON s.assigned_counsellor_id = c.counsellor_id
LEFT JOIN student_remarks sr ON s.student_id = sr.student_id
WHERE (csj.course_status IN ('Form Submitted – Portal Pending', 'Form Submitted – Completed', 'Walkin Completed', 'Walkin Marked', 'Exam/Interview Scheduled', 'Offer Letter/Results Pending', 'Offer Letter/Results Released', 'Ready For Admission')
    OR (csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid'))
    OR csj.course_status = 'Enrolled')
GROUP BY s.student_id, s.student_name, s.student_email, s.student_phone, c.counsellor_name, csj.course_status
HAVING MAX(sr.created_at) < CURRENT_DATE - INTERVAL '7 days' OR MAX(sr.created_at) IS NULL
ORDER BY last_remark_date ASC NULLS FIRST;
```
Key patterns: always include student_email, student_phone, counsellor_name in dormant/no-follow-up queries. For Application/Admission/Enrolled use course_status_journeys.course_status with proper IN list for applications and fee_type filter for admissions, NOT students.current_student_status. Use LEFT JOIN to student_remarks so students with zero remarks also appear. JOIN counsellors via assigned_counsellor_id. No timezone offset — CURRENT_DATE directly for 7-day threshold. No LIMIT.

Question: Show me which counsellors are above or below the team average for conversion rate, and by how much.

```sql
WITH counsellor_metrics AS (
    SELECT
        c.counsellor_id,
        c.counsellor_name,
        COUNT(DISTINCT s.student_id) AS total_students,
        (COUNT(DISTINCT CASE WHEN csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid') THEN csj.student_id END) + COUNT(DISTINCT CASE WHEN csj.course_status = 'Enrolled' THEN csj.student_id END)) AS conversions,
        ROUND(
            (COUNT(DISTINCT CASE WHEN csj.course_status = 'Admission' AND csj.fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid') THEN csj.student_id END) + COUNT(DISTINCT CASE WHEN csj.course_status = 'Enrolled' THEN csj.student_id END))::numeric
            / NULLIF(COUNT(DISTINCT s.student_id), 0) * 100, 2
        ) AS conversion_rate_pct
    FROM counsellors c
    JOIN students s ON c.counsellor_id = s.assigned_counsellor_id
    LEFT JOIN course_status_journeys csj ON s.student_id = csj.student_id
    GROUP BY c.counsellor_id, c.counsellor_name
    HAVING COUNT(DISTINCT s.student_id) > 0
),
benchmark AS (
    SELECT
        ROUND(AVG(conversion_rate_pct), 2)   AS avg_conversion_rate,
        ROUND(STDDEV(conversion_rate_pct), 2) AS stddev_conversion_rate
    FROM counsellor_metrics
)
SELECT
    cm.counsellor_name,
    cm.total_students,
    cm.conversions,
    cm.conversion_rate_pct,
    b.avg_conversion_rate AS team_avg_pct,
    ROUND(cm.conversion_rate_pct - b.avg_conversion_rate, 2) AS diff_from_avg,
    CASE
        WHEN cm.conversion_rate_pct >= b.avg_conversion_rate + b.stddev_conversion_rate THEN 'Above Average'
        WHEN cm.conversion_rate_pct <= b.avg_conversion_rate - b.stddev_conversion_rate THEN 'Below Average'
        ELSE 'Average'
    END AS performance_band
FROM counsellor_metrics cm
CROSS JOIN benchmark b
ORDER BY cm.conversion_rate_pct DESC;
```
Key patterns: Step 1 CTE computes per-counsellor metrics. Step 2 CTE computes AVG + STDDEV across ALL counsellors (global benchmark — NOT a sub-team average). Final SELECT uses CROSS JOIN so every counsellor row gets the benchmark columns. Always output team_avg_pct and diff_from_avg as explicit columns. No LIMIT.

Question: For each degree type, which courses have the most student interest and how many students have shortlisted each one?

```sql
SELECT 
    uc.degree_name,
    uc.course_name,
    COUNT(DISTINCT csj.student_id) AS interested_students,
    COUNT(DISTINCT CASE WHEN lcs.latest_course_status = 'Shortlisted' THEN lcs.student_id END) AS shortlisted_students,
    ROUND(COUNT(DISTINCT CASE WHEN lcs.latest_course_status = 'Shortlisted' THEN lcs.student_id END)::numeric * 100.0 / NULLIF(COUNT(DISTINCT csj.student_id), 0), 2) AS shortlist_rate_pct
FROM university_courses uc
LEFT JOIN course_status_journeys csj ON uc.course_id = csj.course_id AND csj.student_id IN (SELECT student_id FROM students)
LEFT JOIN latest_course_statuses lcs ON uc.course_id = lcs.course_id AND lcs.student_id = csj.student_id
GROUP BY uc.degree_name, uc.course_name
ORDER BY uc.degree_name, interested_students DESC;
```
Key patterns: "student interest" / "students interested in a course" = COUNT(DISTINCT student_id) from course_status_journeys — students who have taken action on this course. NEVER use students.preferred_course for interest metrics (that's only for self-stated preferences). NEVER use latest_course_statuses for general interest counts (it's ONLY for shortlisted and API status). For shortlisted count, use CASE WHEN with latest_course_status = 'Shortlisted' from latest_course_statuses. Always join lcs with both course_id AND student_id to avoid duplication. No LIMIT unless asking for "top N".

Question: For each university, show total admitted students, total course worth, total deposit collected, fee remaining, and breakdown of students by payment type (semester paid, full fee paid, annual paid, partially paid, registration done, etc.)?

```sql
WITH admitted_students AS (
    SELECT
        student_id,
        course_id,
        MIN(created_at) AS first_admission_date
    FROM course_status_journeys
    WHERE course_status = 'Admission'
      AND fee_type NOT IN ('Partial Done', 'Partial Paid', 'Partially Paid')
      AND student_id IN (SELECT student_id FROM students)
    GROUP BY student_id, course_id
),
deduped_payments AS (
    SELECT DISTINCT ON (student_id, course_id, fee_type, created_at::DATE)
        student_id,
        course_id,
        deposit_amount,
        INITCAP(TRIM(fee_type)) AS fee_type_clean
    FROM course_status_journeys
    WHERE deposit_amount > 0
      AND student_id IN (SELECT student_id FROM students)
    ORDER BY student_id, course_id, fee_type, created_at::DATE, created_at DESC
),
payments AS (
    SELECT
        student_id,
        course_id,
        SUM(deposit_amount) AS total_deposit_collected
    FROM deduped_payments
    GROUP BY student_id, course_id
)
SELECT
    uc.university_name,
    COUNT(DISTINCT adm.student_id)                                        AS total_admitted_students,
    SUM(uc.total_fees)                                                    AS total_course_worth,
    COALESCE(SUM(p.total_deposit_collected), 0)                           AS total_deposit_collected,
    SUM(uc.total_fees) - COALESCE(SUM(p.total_deposit_collected), 0)      AS total_fee_remaining,
    COUNT(DISTINCT CASE WHEN dp.fee_type_clean = 'Admission Block' THEN dp.student_id END) AS Admission_block,
    COUNT(DISTINCT CASE WHEN dp.fee_type_clean = 'Admission Blocked'      THEN dp.student_id END) AS Admission_block_1,
    COUNT(DISTINCT CASE WHEN dp.fee_type_clean = 'Counselling Yet to be Done'        THEN dp.student_id END) AS counselling_yet_to_be_done,
    COUNT(DISTINCT CASE WHEN dp.fee_type_clean IN ('Partially Paid', 'Partial Done', 'Partial Paid') THEN dp.student_id END) AS partially_paid,
FROM admitted_students adm
JOIN university_courses uc
    ON adm.course_id = uc.course_id
LEFT JOIN payments p
    ON adm.student_id = p.student_id
   AND adm.course_id  = p.course_id
LEFT JOIN deduped_payments dp
    ON adm.student_id = dp.student_id
   AND adm.course_id  = dp.course_id
GROUP BY
    uc.university_name
ORDER BY
    total_deposit_collected DESC;
```
Key patterns: Use MIN(created_at) per (student_id, course_id) in admitted_students CTE to get first admission event with proper fee_type filter — never filter raw rows directly. Use DISTINCT ON (student_id, course_id, fee_type, created_at::DATE) ORDER BY ... created_at DESC in deduped_payments to remove duplicate payment rows and ensure latest correction wins. NEVER include deposit_amount in DISTINCT ON key. Apply INITCAP(TRIM(fee_type)) to normalize inconsistent casing before CASE WHEN comparisons. Payments CTE aggregates deposit per student-course after deduplication. Final SELECT joins admitted_students → university_courses (for total_fees and university_name), LEFT JOINs payments (for deposit sum), LEFT JOINs deduped_payments again (for per-fee-type breakdown). COALESCE(SUM(...), 0) handles students with no payment rows. Always guard child table queries with student_id IN (SELECT student_id FROM students) to exclude orphaned records.

Question: Show me each counsellor's login and logout time for today (first and last remark between 9:30 AM to 8:30 PM).

```sql
SELECT
    c.counsellor_name,
    MIN(sr.created_at AT TIME ZONE 'Asia/Kolkata') AS login_time,
    MAX(sr.created_at AT TIME ZONE 'Asia/Kolkata') AS logout_time,
    EXTRACT(EPOCH FROM (MAX(sr.created_at) - MIN(sr.created_at))) / 3600 AS working_hours
FROM counsellors c
JOIN student_remarks sr ON c.counsellor_id = sr.counsellor_id
WHERE sr.created_at >= CURRENT_DATE - INTERVAL '5 hours 30 minutes'
  AND sr.created_at < CURRENT_DATE + INTERVAL '1 day' - INTERVAL '5 hours 30 minutes'
  AND EXTRACT(HOUR FROM sr.created_at AT TIME ZONE 'Asia/Kolkata') * 60 + EXTRACT(MINUTE FROM sr.created_at AT TIME ZONE 'Asia/Kolkata') BETWEEN 570 AND 1230
  AND sr.student_id IN (SELECT student_id FROM students)
GROUP BY c.counsellor_id, c.counsellor_name
ORDER BY login_time ASC;
```

For a specific counsellor:
```sql
SELECT
    c.counsellor_name,
    MIN(sr.created_at AT TIME ZONE 'Asia/Kolkata') AS login_time,
    MAX(sr.created_at AT TIME ZONE 'Asia/Kolkata') AS logout_time,
    EXTRACT(EPOCH FROM (MAX(sr.created_at) - MIN(sr.created_at))) / 3600 AS working_hours
FROM counsellors c
JOIN student_remarks sr ON c.counsellor_id = sr.counsellor_id
WHERE sr.created_at >= CURRENT_DATE - INTERVAL '5 hours 30 minutes'
  AND sr.created_at < CURRENT_DATE + INTERVAL '1 day' - INTERVAL '5 hours 30 minutes'
  AND EXTRACT(HOUR FROM sr.created_at AT TIME ZONE 'Asia/Kolkata') * 60 + EXTRACT(MINUTE FROM sr.created_at AT TIME ZONE 'Asia/Kolkata') BETWEEN 570 AND 1230
  AND sr.student_id IN (SELECT student_id FROM students)
  AND c.counsellor_name ILIKE '%counsellor_name%'
GROUP BY c.counsellor_id, c.counsellor_name;
```
Key patterns: "login" is defined as the first remark between 9:30 AM (570 minutes from midnight) to 8:30 PM (1230 minutes from midnight) for that day. Use MIN(created_at) for login time and MAX(created_at) for logout time. Filter remarks using time-of-day calculation: `EXTRACT(HOUR FROM created_at AT TIME ZONE 'Asia/Kolkata') * 60 + EXTRACT(MINUTE FROM created_at AT TIME ZONE 'Asia/Kolkata') BETWEEN 570 AND 1230`. Always apply IST timezone conversion and today's date filter. Always guard with student_id IN (SELECT student_id FROM students). For specific counsellor queries, add `c.counsellor_name ILIKE '%name%'` filter.

Question: Give me yesterday's daily activity summary — how many students had their first ICC, how many turned NotInterested for the first time, how many were first connected, and how many unique students had any remark activity?

```sql
WITH first_icc AS (
    SELECT COUNT(DISTINCT student_id) AS icc_count
    FROM students
    WHERE first_icc_date >= CURRENT_DATE - INTERVAL '1 day' - INTERVAL '5 hours 30 minutes'
      AND first_icc_date < CURRENT_DATE - INTERVAL '5 hours 30 minutes'
),
first_ni AS (
    SELECT COUNT(*) AS ni_count
    FROM (
        SELECT DISTINCT ON (sr.student_id) 
               sr.created_at AS first_ni_at
        FROM student_remarks sr
        INNER JOIN students s ON sr.student_id = s.student_id
        WHERE s.current_student_status = 'NotInterested'
        ORDER BY sr.student_id, sr.created_at ASC
    ) sub
    WHERE first_ni_at >= CURRENT_DATE - INTERVAL '1 day' - INTERVAL '5 hours 30 minutes'
      AND first_ni_at < CURRENT_DATE - INTERVAL '5 hours 30 minutes'
),
first_connected AS (
    SELECT COUNT(DISTINCT student_id) AS connected_count
    FROM (
        SELECT student_id, MIN(created_at) AS first_connected_at
        FROM student_remarks
        WHERE calling_status = 'Connected'
        GROUP BY student_id
    ) sub
    WHERE first_connected_at >= CURRENT_DATE - INTERVAL '1 day' - INTERVAL '5 hours 30 minutes'
      AND first_connected_at < CURRENT_DATE - INTERVAL '5 hours 30 minutes'
),
total_remarks AS (
    SELECT COUNT(DISTINCT student_id) AS unique_remarks_count
    FROM student_remarks
    WHERE created_at >= CURRENT_DATE - INTERVAL '1 day' - INTERVAL '5 hours 30 minutes'
      AND created_at < CURRENT_DATE - INTERVAL '5 hours 30 minutes'
      AND student_id IN (SELECT student_id FROM students)
)
SELECT 
    (SELECT icc_count FROM first_icc) AS total_first_icc,
    (SELECT ni_count FROM first_ni) AS total_first_ni,
    (SELECT connected_count FROM first_connected) AS total_first_connected,
    (SELECT unique_remarks_count FROM total_remarks) AS total_unique_remarks;
```
Key patterns: "yesterday" in IST = CURRENT_DATE - INTERVAL '1 day' - INTERVAL '5 hours 30 minutes' as lower bound AND CURRENT_DATE - INTERVAL '5 hours 30 minutes' as upper bound — always apply both offsets for IST day boundaries. first_icc uses students. first_icc_date. first_ni uses DISTINCT ON to get the earliest remark per student, then filters by date — only students currently in NotInterested status. first_connected uses MIN(created_at) per student from student_remarks where calling_status = 'Connected'. unique_remarks counts DISTINCT student_id from student_remarks in the window. Final SELECT uses scalar subqueries from each CTE — returns exactly one summary row. Always guard student_remarks with student_id IN (SELECT student_id FROM students).
